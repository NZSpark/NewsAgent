## 1. 项目目标与范围

### 1.1 最终交付目标

- [x] NewsAgent 可通过二维码登录微信 iLink Bot。（真实账号登录已实测通过）
- [x] 用户可通过主动向 Bot 发送消息的方式，将自己的个人微信绑定为唯一收件人。（真实账号已实测通过）
- [x] 可独立执行微信登录、状态查询、收件人绑定、发送和退出登录命令。
- [x] 发送模式：**仅 `summary`（单条摘要文本）**。设计修订（2026-10-10）移除了 `full` 与 `summary_pdf`。
- [x] 默认使用 `summary` 模式，并可由配置及命令行覆盖。
- [x] 复用已经生成的摘要；微信发送模块不负责生成报告、重新提炼摘要或补生成 PDF。
- [x] 默认发送最新报告，也允许手动指定单个报告文件。
- [x] 支持现有 `news report` 命令显式附带微信发送功能，未指定发送选项时不改变原有行为。
- [x] 支持系统调度器执行每日定时任务，包含报告生成后发送和直接发送已有报告两种方式。（模板与文档已就绪；真机验收待 TASK-132/136/171/172）
- [x] 发送失败时按默认策略最多重试 3 次，每次间隔 10 秒；这两个参数可在配置中修改。
- [x] 支持发送状态、失败诊断、部分成功记录、不确定发送保护和定时任务的重复执行保护。
- [x] 提供 macOS `launchd` 与 Linux `cron` 的模板及使用说明，由用户自行安装。
- [x] 完成自动化测试、真实微信端到端测试与许可证检查；目标系统真机定时任务验证待完成（TASK-132/136/171/172）。

### 1.2 明确不做的事情

- 不支持微信群或多个收件人。
- 不要求运行 Hermes 或 OpenClaw Gateway。
- 不增加 NewsAgent 内部常驻调度器。
- 不自动安装、修改或卸载系统定时任务。
- 不在微信发送流程中生成报告、摘要或 PDF。
- 不默认重试认证错误、输入文件缺失等不可通过重试解决的问题。

## 14. 关键技术规则与风险

### 14.1 重试并不自动保证恰好一次发送

网络超时可能发生在服务端已接收消息之后。重试可能造成重复发送。实现时优先使用协议提供的消息 ID、幂等键或状态查询能力；若接口不支持，必须在文档中说明该限制。

### 14.2 摘要与 PDF 发送不是原子事务

摘要消息和附件可能是独立请求。实现时分别记录状态；附件失败后不得无条件重复发送已确认成功的摘要。输入配对与存在性检查应尽可能在第一次网络发送前全部完成。

### 14.3 iLink 上下文不应被假定为永久有效

应确认协议令牌的有效期、更新与持久化条件。过期时返回明确错误，并指导用户重新建立会话。不得把模拟测试结果当作真实微信协议已经验证。

### 14.4 新 CLI 接口需要与实际项目一致

本任务文件列出的 `news wechat ...` 和新增参数是目标接口。编码前必须对齐现有 CLI 框架、参数命名、异常处理与退出码规则。

### 14.5 定时任务模板不负责安装

模板只提供可编辑配置和操作说明，用户自行安装。必须使用绝对路径并说明环境变量、工作目录、日志和本地时区规则。

5. iLink 发送客户端及 `summary` 模式。
6. 错误分类、重试、发送状态与日志。
7. 独立 CLI 与 `news report` 集成。
8. `launchd`/`cron` 模板和使用文档。
9. 完整测试、安全审查和端到端结果。

每个提交应尽量保持职责单一，并至少运行对应的测试。协议相关代码的复用或移植应保留必要来源信息和许可证说明。

### 15.2 每个任务的完成定义

一个任务只有同时满足适用的以下条件才算完成：

- 实现代码或交付文件已经落地。
- 对应测试已补齐并通过，或明确说明为什么不能自动化测试。
- 错误路径和边界条件已覆盖。
- 日志没有暴露敏感信息。
- 相关配置、命令或文档已同步更新。
- 没有把尚未验证的协议行为表述为已实现或已确认。

### 15.3 进度记录

开始实施后，可在每个任务前标记状态：

- `[ ]` 未开始。
- `[-]` 进行中。
- `[x]` 已完成并验证。
- `[!]` 阻塞，需要先解决依赖或协议问题。

完成时应记录实际验证结果。规划清单中的任务默认均为未开始，不代表现有代码已经完成相应功能。
